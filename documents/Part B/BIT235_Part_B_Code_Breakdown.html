1. What the Application Does

This project extends the Part A login system into a Spring Boot MVC wiki application. Visitors can read articles and browse categories without logging in. An admin can log in and create, edit, or delete articles.

The project follows the Controller, Service, Repository, Model, and View structure used in class. It also uses sessions for admin login, BCrypt password hashing, an H2 database, Thymeleaf templates, CSS, JavaScript validation, and JUnit tests.

5. MVC Request Flow

Simple explanation for the demonstration: Browser request goes to a Controller. The Controller calls a Service. The Service uses a Repository if data is needed. The Controller adds results to the Model and returns a Thymeleaf page.

Example for the home page:

  1. The browser opens /.
  2. PublicController.home() receives the request.
  3. It calls ArticleService.findRecentArticles().
  4. The service uses ArticleRepository to get recent articles from H2.
  5. The controller puts the articles into the model.
  6. Thymeleaf renders home.html.

6. Main Java Classes

WikiAdminApplication.java

This starts the Spring Boot application. It also defines a shared PasswordEncoder bean so the same BCrypt encoder is used when seeding and checking admin passwords.

AuthController.java

This handles /login and /logout. On a successful login it stores the admin object in the session using the name loggedInAdmin. On logout it clears the session.

PublicController.java

This handles public pages: home, article list, single article, categories, and articles by category. These pages do not require login.

AdminController.java

This handles the article management pages. It supports create, edit, save, and delete. If validation fails, it returns the form with clear error messages.

AdminAccessInterceptor.java and WebConfig.java

The interceptor checks all /admin pages before the controller runs. If the session does not contain loggedInAdmin, the user is sent to /login.

DataSeeder.java

This inserts starter records when the app starts. It creates the admin accounts, categories, and sample articles. This makes the app ready to demonstrate straight away.

7. Models and Database

Model What it Represents
Admin Admin username, display name, and hashed password.
Category A topic group such as History, Science, or Programming.
Article A wiki article with title, content, created date, and one category.
LoginForm Temporary form data for login.
ArticleForm Temporary form data for creating and editing articles.

Each article belongs to one category. A category can have many articles. This is handled using JPA annotations in the model classes.

8. Article CRUD Workflow

Create

Admin clicks Create New Article, fills in the form, JavaScript checks the fields, and the form posts to /admin/articles/save. The service validates again before saving.

Read

Visitors can read article previews on the home page and full articles on the detail page.

Update

Admin clicks Edit, changes the form, confirms save, and the same save method updates the existing article.

Delete

Admin clicks Delete. JavaScript asks for confirmation. If confirmed, the controller calls the service to delete the article.

9. Password Hashing and Sessions

The application does not store plain text admin passwords. DataSeeder stores passwords using BCrypt. During login, AuthService.authenticate() checks the submitted password against the stored hash.

The session keeps the admin logged in while moving between pages. The app checks the session before showing admin pages. Logging out invalidates the session.

10. Validation

The article form uses HTML required fields and a minimum content length. validation.js adds client-side checks and save/delete confirmation. ArticleService.validateArticleForm() repeats the important checks on the server, so invalid data is still rejected if JavaScript is bypassed.
